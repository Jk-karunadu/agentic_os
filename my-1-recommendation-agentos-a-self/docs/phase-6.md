# Phase 6 — Tool-Use Integration

## What is implemented

### Tool Abstraction & Registry
Added `BaseTool` (abstract class) and `ToolRegistry` to manage external capabilities. The registry translates our internal tool definition into OpenAI-compatible JSON schema arrays, which are consumed by the local LLM.

### Implemented Tools
1. **`MemoryQueryTool`**: Connects the `ResearchWorker` directly to the `MemoryStore`.
   - Allows agents to dynamically search past episodic/procedural memories or semantic facts without explicitly loading them into the initial context window.
   - Takes a `query`, optional `type` filter, and returns the top matches.
2. **`WebSearchTool`**: Uses the Wikipedia API to provide live web search capabilities.
   - Takes a `query`, runs an OpenSearch query, and fetches the page summary extract.
   - Useful for augmenting tasks with external facts that aren't provided in the initial evidence.

### Agentic Loop inside `ResearchWorker`
The `ResearchWorker` now implements a ReAct-style loop:
- It invokes the LLM (`OllamaClient.chat()`) with `tools` provided in the JSON payload.
- It intercepts any `tool_calls` generated by the model.
- It parses the JSON arguments, executes the requested tool via `ToolRegistry`, and appends the result as a `"tool"` role message to the message history.
- It loops automatically until the LLM generates a final text response (up to `max_tool_calls` defined in the task budget).
